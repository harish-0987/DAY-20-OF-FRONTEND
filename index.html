Foundation & Language Core

The 8 JavaScript Data Types

JavaScript is dynamically typed: identifiers do not carry static types—the values themselves carry types. Modern ECMAScript defines exactly 8 built-in types divided into 7 Primitives and 1 Reference type.

Primitive typeof → "string"

String

Represents textual UTF-16 data enclosed in single quotes, double quotes, or template literal backticks.

const greeting = "Hello World";
Primitive typeof → "number"

Number

Double-precision 64-bit binary format IEEE 754. Handles integers, decimals, Infinity, -Infinity, and NaN.

const pi = 3.14159; // also NaN
Primitive typeof → "bigint"

BigInt

Introduced in ES2020 to represent arbitrary-precision integers beyond Number.MAX_SAFE_INTEGER (253 - 1).

const largeNum = 9007199254740995n;
Primitive typeof → "boolean"

Boolean

A logical entity representing binary truth states: exactly true or false.

const isCompleted = true;
Primitive typeof → "undefined"

Undefined

Automatically assigned by the JavaScript engine to declared variables that have not yet been assigned a value.

let user; // undefined
Primitive typeof → "object" ⚠️

Null

Represents the intentional absence of any object reference. Note: typeof null === "object" is a 1995 legacy bug.

const selectedItem = null;
Primitive typeof → "symbol"

Symbol

Introduced in ES6 to produce guaranteed globally unique, immutable identifiers, ideal for hidden object keys.

const id = Symbol('userId');
Reference Type typeof → "object"

Object (Non-Primitive)

Complex keyed collections and data structures. Includes Plain Objects {}, Arrays [], Functions, Dates, and Maps.

const user = { name: "Harish" };
Memory Architecture

Memory Allocation: Call Stack vs Memory Heap

The engine uses two distinct memory areas. Primitives are stored directly by value in the Stack; objects are stored in the Heap, with the Stack holding only memory references.

⚡

Call Stack (Primitives)

  • Storage: Stores primitive values and execution contexts.
  • Access: Ultra-fast, ordered LIFO (Last-In, First-Out) memory.
  • Copying: Copied by Value. Mutating one variable creates a distinct copy without affecting original.
  • Immutability: Primitive data cannot be mutated in place; reassignment writes a new value.
let score1 = 100;
let score2 = score1; // Independent copy!
score2 = 200;
console.log(score1); // 100 (Untouched)
🌐

Memory Heap (Reference Types)

  • Storage: Stores dynamically-sized objects, arrays, and functions.
  • Access: Slower, random-access memory managed by Garbage Collector.
  • Copying: Copied by Reference. Assigning an object copies only the memory pointer (#0x101).
  • Mutability: Properties can be freely modified, affecting all pointers pointing to that heap location.
const user1 = { name: "Harish" };
const user2 = user1; // Copies pointer address!
user2.name = "Alex";
console.log(user1.name); // "Alex" (Mutated!)

Engine Mechanics

Type Conversion: Explicit vs Implicit Coercion

Type conversion converts a value from one data type to another. Explicit conversion is intentional; Implicit coercion happens automatically under the hood when operators encounter mismatched types.

1. Explicit Type Casting

Constructors called as functions to cleanly transform types:

// String Conversion:
String(123);        // "123"
String(false);      // "false"

// Numeric Conversion:
Number("42");       // 42
Number("");         // 0
parseInt("24px");   // 24
+"99";              // 99 (Unary +)

// Boolean Conversion:
Boolean(1);         // true
Boolean(0);         // false
!!"hello";          // true (Double-bang)

2. Implicit Type Coercion

Rules the JavaScript engine follows during evaluations:

// Plus (+) with a string triggers String Concatenation:
"5" + 2;            // "52" (Number 2 coerced to "2")

// Math operators (-, *, /, %) trigger Numeric Coercion:
"5" - 2;            // 3    ("5" coerced to number 5)
"6" * "4";          // 24   (Both coerced to numbers)

// Boolean contexts (if, &&, ||) trigger Truthy/Falsy check:
if ("text") { ... } // Evaluates as true!

⚠️ The Exact 8 Falsy Values in JavaScript

In JavaScript, EVERYTHING is truthy except these exact 8 values:

false 0 -0 0n "" (empty string) null undefined NaN
💡 Watch Out: [] (empty array), {} (empty object), "0" (string with zero), and "false" are all TRUTHY!

Strict (===) vs Loose (==) Battle Arena

Loose equality performs implicit type coercion according to the abstract equality algorithm, while strict equality checks both type and value. Test classic tricky interview comparisons below.

Famous Matchups:
Loose Equality A == B
5 == '5'
true
Coercion Algorithm:

Operands have different types (number vs string). The engine coerces the string '5' into the number 5, resulting in 5 == 5.

Strict Equality A === B
5 === '5'
false
Strict Algorithm:

Types are different (typeof A is "number", typeof B is "string"). Strict equality terminates immediately and returns false with zero coercion.

Technical Interview Prep

Top Frontend Interview Questions & Answers

Master the essential questions asked by top engineering companies regarding JavaScript types, memory, and coercion.

❓ Q1: What is the fundamental difference between null and undefined?

Answer:

  • undefined represents the automatic default state of a declared variable before any assignment (or a function with no return).
  • null is an intentional assignment representing an explicit empty reference or "no object value".
  • typeof undefined returns "undefined", whereas typeof null returns "object" (a famous 1995 legacy bug).
  • In loose equality, null == undefined is true. In strict equality, null === undefined is false.
❓ Q2: Why does 0.1 + 0.2 !== 0.3 in JavaScript? How should you fix it?

Answer:

JavaScript represents numbers as IEEE 754 64-bit binary floating-point. In binary base-2, numbers like 0.1 and 0.2 are recurring repeating fractions (like 1/3 in decimal base-10). The resulting sum is 0.30000000000000004.

Fix: Use Number.EPSILON for comparison, or round via .toFixed() or multiply to integer cents:

const areEqual = Math.abs((0.1 + 0.2) - 0.3) < Number.EPSILON; // true
❓ Q3: How does JavaScript evaluate the expression [] == ![]?

Answer: It evaluates to true via step-by-step coercion:

  1. Unary operator ! has higher precedence than ==. Since [] is an object, it is truthy. Thus ![] becomes false.
  2. The expression becomes [] == false.
  3. Loose equality coerces boolean false to number 0: [] == 0.
  4. Comparing an object (array) to a number coerces the array via .toString(): [].toString() === "".
  5. Empty string "" coerced to number becomes 0.
  6. The expression is now 0 == 0, which is true!
❓ Q4: What is the difference between Logical OR (||) and Nullish Coalescing (??)?

Answer:

  • || falls back to the right operand on ANY falsy value (including 0, "", and false). This often introduces bugs when valid settings like zero count or empty string get overwritten.
  • ?? falls back ONLY on nullish values (null or undefined). It correctly preserves 0, "", and false.

8 Data Types

7 Primitives (string, number, bigint, boolean, undefined, null, symbol) stored in Stack; 1 Reference (object) stored in Heap.

02

Stack vs Heap

Primitives are copied by value (immutable). Reference types are copied by pointer address (mutable).

03

Strict Equality

Always default to === and !== to prevent unintended implicit type coercion bugs.

Modern Operators

Use ?? for safe default fallbacks and ?. for safe deep object navigation without crashes.

The 8 Falsy Values

Explicit Casting

Prefer readable explicit conversions like Number(x) and Boolean(x) over hidden coercion.
