Architecture & Language Design

Core Features of JavaScript

JavaScript is a high-level, multi-paradigm, dynamically typed language engineered to run in client browsers and modern server runtimes. Here are the core pillars that define its behavior:

⚡

High-Level & JIT-Compiled

No manual memory management or static compiling required.

Modern browser engines (Google V8, Mozilla SpiderMonkey) use Just-In-Time (JIT) compilation to translate JavaScript into optimized machine code on the fly during execution.

Engine: V8 / SpiderMonkey Memory: Automatic Garbage Collection
🔄

Dynamically & Weakly Typed

Variables hold values, not rigid types.

You don't declare data types ahead of time. A variable holding a number can later hold a string. JavaScript also performs type coercion when combining different types.

Typing: Dynamic runtime binding Inspection: typeof operator
🧵

Single-Threaded & Non-Blocking

One main call stack powered by the Event Loop.

JavaScript executes code one statement at a time on a single thread. To handle heavy tasks (network requests, timers) without freezing the UI, it delegates them to Web APIs and the Event Loop.

Concurrency: Event Loop Execution: Non-blocking I/O
🎭

Multi-Paradigm Language

Flexible programming styles suited for any architecture.

Supports Procedural (step-by-step), Object-Oriented (classes, encapsulation, prototype chains), and Functional Programming (pure functions, immutability, map/filter/reduce).

Styles: OOP + Functional Inheritance: Prototype-based
🎯

First-Class Functions

Functions treated as first-class citizens.

Functions can be stored in variables, passed into other functions as arguments (callbacks), returned from functions (closures), and assigned properties just like objects.

Patterns: Callbacks & Closures Usage: Higher-Order Functions
🌐

Cross-Platform Ubiquity

Run anywhere: Browser, Server, Mobile, Desktop.

Originally designed solely for web browsers, modern JavaScript now powers backends (Node.js, Deno, Bun), mobile applications (React Native), and desktop apps (Electron).

Specification: ECMAScript (TC39) Standard: Living Web Standard
Memory & State

Variables in JavaScript: var vs let vs const

A variable is a named container in memory that stores a reference to a data value. In modern JavaScript, how you declare that container dictates its lifetime, scope, and mutability.

var Legacy (ES1 - 1995)

Function-Scoped Variable

The original variable declaration keyword from JavaScript's inception. Known for subtle bugs due to lack of block scoping and loose re-declaration rules.

  • 📦 Scope: Function-scoped (ignores { } blocks)
  • ♻️ Re-declaration: Allowed in same scope (dangerous!)
  • ✏️ Re-assignment: Allowed at any time
  • 🎈 Hoisting: Hoisted and initialized to undefined
  • 🌐 Global: Attaches to window object in browsers
var count = 1;
var count = 2; // Allowed! Silently overwrites
let Modern Standard (ES6 - 2015)

Block-Scoped Mutable Variable

Introduced in ECMAScript 2015 (ES6) to fix var's design flaws. Confined strictly to the curly braces { } where it is created.

  • 🧱 Scope: Block-scoped { ... }
  • 🚫 Re-declaration: Forbidden in the same scope
  • ✏️ Re-assignment: Allowed (perfect for counters/state)
  • ⏳ Hoisting: Hoisted into Temporal Dead Zone (TDZ)
  • 🛡️ Global: Does not pollute window object
let score = 10;
score = 20; // OK (Re-assignment allowed)
const Best Practice Default (ES6)

Block-Scoped Constant Binding

Declares an immutable variable binding. The variable identifier cannot be reassigned to a new value once initialized. Recommended default for 90% of code.

  • 🧱 Scope: Block-scoped { ... }
  • 🚫 Re-declaration: Forbidden in the same scope
  • 🔒 Re-assignment: Strictly Forbidden (TypeError)
  • ⏳ Hoisting: Hoisted into Temporal Dead Zone (TDZ)
  • 📦 Mutation: Object/Array contents CAN be mutated!
const API_URL = "https://api.dev";
// API_URL = "new"; ❌ TypeError!

Lab 3: Hoisting & The Temporal Dead Zone (TDZ)

Before executing your code line-by-line, the JavaScript engine performs a Creation Phase to scan declarations. Step through the timeline below to see why var gives undefined while let throws a ReferenceError.

PHASE 01

Creation Phase

JS Engine scans all code. var a is registered in memory and assigned undefined. let b is registered in memory but left completely uninitialized.

PHASE 02

Temporal Dead Zone

The zone between entering scope and the line where let/const is declared. Accessing b here triggers ReferenceError: Cannot access 'b' before initialization!

PHASE 03

Execution Phase

Code runs sequentially. The line let b = 50 is reached. b exits the TDZ and is initialized to 50. Safe to read and use!

Best Practices

Modern JavaScript Variable Golden Rule

👑

The 1-2-3 Rule for Modern Variables

1. Default to const for all declarations. It produces predictable code, prevents accidental mutations, and signals developer intent.
2. Use let only when re-assignment is needed (e.g., loop counters, accumulator sums, toggle flags).
3. Never use var in modern code. It has no block scope, pollutes global scope, and introduces hoisting bugs.

✅
Block Scoping: let and const are bound to curly braces { }. They do not leak into outer code blocks.
✅
Temporal Dead Zone (TDZ): You cannot access let or const before their declaration line. Doing so throws a ReferenceError.
✅
const Mutability: const locks the variable binding, not the contents of arrays or objects. You can still modify properties!
✅
Dynamic Typing: Variables can hold any data type at runtime. Always verify unexpected types with typeof.
